# Larry 教材 Web 项目

这个结构用于 GitHub 和两台电脑同步维护。

## 目录

- `source/`：Markdown 源文件，后续主要编辑这里。
- `web/`：HTML 查询页面。
- `assets/`：图片素材。
- `docs/`：Word、Excel 等导出文件可放这里。

## 推荐工作流

1. 修改 `source/*.md`，其中 `source/full-summary.md` 是完整讲义主文本。
2. 若需要网页同步展示，再更新 `web/app.js` 中对应模块。
3. 用浏览器打开 `web/index.html` 查询。
4. 用 GitHub 保存版本历史。

## 展示原则

- 网页中的课程截图不直接使用原始截图，而是重绘成统一风格的信息图。
- 颜色标注使用浅底深字标签，避免纯色文字导致阅读困难。
- HTML 是查询版；Markdown 是源文件；Word/Excel 是导出版。

## 颜色规则

这是本项目的硬性规则。后续新增内容、网页展示、Markdown 源文件、Word/Excel 导出版，都必须严格按照以下对应关系标注。

- 名词性成分：红色
- 形容词性成分：黄色
- 副词性成分：绿色
- 非谓语 / 不定式：紫色

## 两台电脑维护流程

核心口诀：开工先同步，收工就上传。

### 开始编辑前

文字动作：同步最新版。

含义：把 GitHub 上另一台电脑刚改过的内容，先下载到当前电脑。

### 编辑过程中

文字动作：正常修改文件。

含义：像平时一样修改 Markdown、网页、Word 或资料文件。

### 编辑完成后

文字动作：暂存修改、提交修改、推送修改。

含义：

- 暂存修改：告诉 Git 哪些文件要保存。
- 提交修改：给这次修改起一个名字，形成一个可回退的版本。
- 推送修改：把这次版本上传到 GitHub，让另一台电脑可以同步到。

### 两台电脑轮流使用

1. A 电脑改完：暂存修改 -> 提交修改 -> 推送修改。
2. B 电脑开始改前：同步最新版。
3. B 电脑改完：暂存修改 -> 提交修改 -> 推送修改。
4. A 电脑下次继续前：同步最新版。

不要让两台电脑同时修改同一个文件。尤其是 `web/app.js`、`source/preposition.md` 这类常改文件，最好一台电脑上传后，另一台电脑先同步再继续。
